7. Deep Call Chain (10 nested functions)

validate_header(struct{magic=0x50524f54, version=1, offset=0x10, size=0x30})
  ← returned 0 (PASSED — no offset bounds check!)
transform_data(struct{session_id, key=3})
  ← returned 0x30 (= 16 × 3 = 48)
apply_filter(struct{...}, 48)
  ← returned 0x18 (= 48 >> 1 = 24)
compute_index(0x30, 0x18)
  ← returned 0x8 (= (48+24) & 0xF = 8)
lookup_slot(table, 8)
  → write_slot(table, idx=8)
    → commit_write(table, index=8, 0xdeadc0de00000000)
      ← BUG: table->slots[8] OOB WRITE!
Root cause identified from dataflow alone: validate_header() doesn't check payload_offset bounds, and lookup_slot() uses % 16 instead of % 8.

Conclusion: kcov_dataflow now works for both C and Rust kernel modules. For Rust, a post-compilation pipeline (rustc→opt→llc) instruments the LLVM IR with our sancov pass. drgn vmcore still cannot read Rust locals (rustc -O2 limitation), making kcov_dataflow the only method to capture Rust function arguments at runtime.
