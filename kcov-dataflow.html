KCOV Dataflow: Implementation Specification

Version: 1.0 | Status: PoC Complete | Target: Linux kernel + LLVM/Clang

1. Overview

KCOV Dataflow extends the Linux kernel's KCOV infrastructure with function argument and return value tracing. It provides a separate /sys/kernel/debug/kcov_dataflow device that captures struct field values at function entry and exit, enabling data flow analysis for memory corruption bugs.

Design Principle: Completely independent from legacy /sys/kernel/debug/kcov. Zero interference with existing users (syzkaller, oss-fuzz). Separate buffer, separate ioctl namespace, separate enable flag.

2. Compiler Component

2.1 New Compiler Flags

FlagDescription
-fsanitize-coverage=trace-argsInsert __sanitizer_cov_trace_args() at function entry for each argument
-fsanitize-coverage=trace-retInsert __sanitizer_cov_trace_ret() before each return instruction

Both imply -fsanitize-coverage-type=3 (edge coverage) when used alone.

2.2 LLVM Pass Location

llvm/lib/Transforms/Instrumentation/SanitizerCoverage.cpp
  → InjectTraceForArgs(Function &F)
  → InjectTraceForRet(Function &F)

2.3 Type Extraction (DebugInfo)

  1. Query DISubprogram::getType() → DISubroutineType
  2. For each arg: get DIType from type array
  3. If pointer to DICompositeType (struct): iterate DW_TAG_member elements
  4. Collect (byte_offset, byte_size) pairs into a ConstantArray
  5. Prepend FNV-1a hash of struct name at offsets[-1]

2.4 Callback Signatures

void __sanitizer_cov_trace_args(
    u64 pc,           // Function address
    u32 arg_idx,      // Argument position (0-based)
    u32 arg_size,     // Byte size of argument type
    void *arg_ptr,    // Pointer to argument (or alloca for scalars)
    u64 *offsets,     // [off0, sz0, off1, sz1, ...] for struct fields
    u32 num_fields    // Number of struct fields (0 for scalars)
);

void __sanitizer_cov_trace_ret(
    u64 pc,           // Function address
    u32 ret_size,     // Byte size of return type
    void *ret_val,    // Pointer to return value
    u64 *offsets,     // Struct field layout
    u32 num_fields    // Number of fields
);

2.5 Requirements

  • -g (debug info) is mandatory for struct field expansion
  • -fno-inline recommended to preserve function boundaries
  • Without -g: no trace_args calls emitted (pass returns early)

3.4 Buffer Format (TLV Records)

area[0] = total_words_written (atomic counter, updated via xadd)

Each record:
  [pos+0] = type_and_seq
             bits[31:28] = 0xE (entry) or 0xF (return)
             bits[23:0]  = per-task sequence number
  [pos+1] = PC (function address, canonicalized)
  [pos+2] = meta
             bits[63:56] = arg_idx (entry) or 0 (return)
             bits[55:48] = arg_size or ret_size in bytes
             bits[47:0]  = raw pointer value (lower 48 bits)
  [pos+3..N] = field values (one u64 per struct field)
               or single scalar value if num_fields=0

3.5 Safety Properties

  • Recursion prevention: Callbacks marked notrace __no_sanitize_coverage noinline
  • Fault tolerance: All pointer reads via copy_from_kernel_nofault()
  • Atomic buffer: xadd() for space reservation (no torn writes)
  • Per-task isolation: Buffer in task->kcov_df_area, check task->kcov_df_enabled
  • ERR_PTR handling: Skip struct expansion for error pointers

3.6 task_struct Fields

struct task_struct {
    ...
    u32              kcov_dataflow_seq;  // Per-task TLV sequence counter

# In module Makefile — ONE LINE, no compiler knowledge needed:

5. Compatibility Guarantee

ScenarioLegacy KCOVkcov_dataflow
syzkaller using /sys/kernel/debug/kcovUnchangedNo interference
Both devices open simultaneouslyIndependentIndependent
CONFIG_KCOV_DATAFLOW_ARGS=y, no ioctlZero overheadBool check returns immediately
No printk in data path. The callbacks write only to the mmap buffer. Reasons: performance (printk takes global lock), recursion risk (printk calls instrumented functions), determinism (buffer preserves exact ordering).

6. Mapping with Legacy KCOV

Both buffers record the same PC for the same function. Correlation:

  • Nth occurrence of func+0x0 in kcov PC buffer = Nth ENTRY in kcov_dataflow for that PC
  • Ordering guaranteed by single-task sequential execution
  • No shared counter needed — implicit from program order

8. Implementation Prompt

For AI-assisted implementation:

Implement a "KCOV Dataflow" system that captures function arguments and return values in the Linux kernel. The system has two parts:

  1. LLVM Pass: In SanitizerCoverage.cpp, add InjectTraceForArgs and InjectTraceForRet methods. Use DISubprogram debug metadata to extract struct field offsets. Insert calls to __sanitizer_cov_trace_args(pc, arg_idx, arg_size, ptr, offsets, num_fields) at function entry and __sanitizer_cov_trace_ret(pc, ret_size, ptr, offsets, num_fields) before returns.
  2. Kernel Backend: In kernel/kcov.c, implement the callbacks with notrace __no_sanitize_coverage noinline attributes. Use copy_from_kernel_nofault() for all pointer reads. Create a separate /sys/kernel/debug/kcov_dataflow device with own open/mmap/ioctl/close. Use atomic xadd for buffer reservation. Store state in task->kcov_df_area/kcov_df_enabled.
  3. Build System: Add CFLAGS_KCOV_DATAFLOW to scripts/Makefile.kcov. Add KCOV_DATAFLOW variable handling to scripts/Makefile.lib. Module authors enable with one line: KCOV_DATAFLOW_file.o := y.

Key constraints: never touch legacy /sys/kernel/debug/kcov, no printk in data path, -g required for struct expansion, ERR_PTR values must be skipped.
