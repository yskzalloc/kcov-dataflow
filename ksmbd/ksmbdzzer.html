ksmbdzzer — a dataflow-steered, SMB-procedure-level fuzzer for ksmbd

A high-level, SMB-procedure-level coverage-guided fuzzer for the Linux in-kernel SMB server (ksmbd). It targets write-side integrity violations and non-crashing logic bugs as well as memory-safety bugs. It is steered by kcov-dataflow, which reports kernel function argument and return values and trace_cmp operand pairs, not just edges. 210 active grains cover the SMB1/2/3 procedure surface, ordered by kernel data-path depth (file and VFS I/O first, session and auth last). Grains are combined on a shared object, and engine arms measure the dataflow steering head-to-head against PC-only baselines.

Not a syzkaller. syzkaller fuzzes syscalls with edge coverage and finds crashes. ksmbdzzer fuzzes one layer up, at the SMB procedure level, with dataflow argument/return values, procedure combination, and effect-based oracles for bugs that do not crash. The two look at different things.

System architecture

Design principles

  1. SMB-procedure level, not syscall level. The atom of work is an SMB procedure (CREATE, WRITE, SET_INFO, IOCTL…), not a syscall.
  2. trace-args/ret is the primary signal. kcov-dataflow reports the values a kernel function received and returned. With CONFIG_KCOV_ENABLE_COMPARISONS, the same buffer also carries trace_cmp operand pairs (0xC records), the substrate for RedQueen input-to-state mutation.
  3. Path coverage saturates; values are bounded. The fold keeps a PC-only path region, which saturates and so gives the scheduler a clean signal, plus a first-seen value region. Comparison operands drive the mutator and are never folded into coverage.
  4. Grain = a working scenario. A fixed, valid negotiate + auth + tree + CREATE prefix, with only the last target PDU fuzzed. The grain is deep by construction: mutation starts past the SMB2 parser wall.
  5. Capture normal behavior first. The bare scenario's coverage (ft0) is the baseline. Coverage beyond it counts as progress, and coverage that collapses below it counts as a stability bug.
  6. Four-phase round loop. P1 enumerate → P2 saturate → P3 combine → P4 save/feed-forward.
  7. C fuzzes, Python manages. Mutation, execution and feedback live in the libFuzzer harness. Python enumerates, launches, aggregates and runs the oracles.
  8. libFuzzer must see kernel coverage. Each harness writes the kernel coverage it received into __libfuzzer_extra_counters (ctr[4096]), so libFuzzer's own corpus logic is steered by kernel behavior.
  9. Alignment is the most important step. selftest proves, using kernel PCs, that each grain reaches ksmbd. During a campaign, a grain is ALIGNED only if ft ≥ 100 (ALIGN_MIN_FT). Free-runners are fast-bailed.
  10. Anti-monkey selection. A grain is PRODUCTIVE only if Δ = ft − ft0 ≥ 100 or Δ ≥ 0.2·ft0.
  11. Oracles are checks, not phases. crash · stability · contract (effect-based, cross-user).
  12. Scale via parallel map-reduce. Each grain gets its own loopback IP, and with it its own kernel buffer. Idle cores run replicas that share the grain's corpus.
  13. Feed-forward across generations. The per-grain corpus, the value pool (-dict) and the arbiter blob (fb.bin) are carried into the next round.
  14. Lightweight input-to-state steering. RedQueen-style splicing from real trace_cmp pairs, a persistent operand ring with injection, argument-to-boundary drives and return-value tokens. No SMT, no symbolic execution, no byte-level taint.
  15. Comparable, not just assertible. Engine arms with identical instrumentation make the ablation controlled.

Record layout (v4 UAPI): [0] header = seq[23:0] · type[31:28] (0xE entry / 0xF return / 0xC cmp) · nvals[47:32] · size[55:48] · arg_idx[63:56]; [1] PC; [2] source address, or the cmp type for 0xC; then nvals value words. An unreadable field is stored as 0xBADADD85.

The coverage fold

ctr[4096]  =  PATH region ctr[0..3583]  |  VALUE region ctr[3584..4095]     (raw tier; GRAIN_PATH_N tunes the split)

PATH : every record          ctr[((pc * 0x517cc1b727220a95) >> 12) % 3584]++       # saturates
VALUE: 0xE/0xF, each field k with v ∉ {0, 0xBADADD85}
       b = (((pc ^ κ(v)) + k*0x9E3779B9) * 0x9E3779B97F4A7C15) >> 48
       if !seen[b]: seen[b] = 1; ctr[3584 + b % 512]++                         # first-seen only
CMP  : 0xC operands never enter VALUE → persistent operand ring → mutate_i2s

κ(v) = v                                              (dataflow)
κ(v) = 0 | 0x1000|(v&0x38) ptr | 0x2000 non-canonical | floor(log2 v)   (dataflow-vec)
dataflow-rel adds, per field pair (a,b): ordering {<,=,>}

The library tier implements the same policy with feature hashing: one 64-bit FNV-1a feature per kernel record (PC only for cmp records and the pc-* arms; PC + value-classed fields for vec; PC + classed value for returns), written as ctr[f & 4095]++. Only PCs ≥ 0xffffffff80000000 count. Note: the baseline dataflow arm hashes an entry record's raw value without its PC (libksmbdzzer.c, df_features()).

The mutator — mutate_i2s / pfz_mutate_i2s

LLVMFuzzerCustomMutator(d, seed):
  if arm == pc-havoc or seed % 3 != 0:  return havoc          # 2 of 3 calls stay plain havoc
  grow d to ≥ 16 bytes
  pass 0  for each 0xC (w ≥ 2, a1 ≠ a2): if LE(a1|a2) ∈ d → swap in the other operand
          else remember; INJECT up to 6 operands (this exec + persistent 512-entry ring)
  pass 1  collect this exec's returns (+ persistent 512-entry return dict)
  pass 2  for each 0xE field v found in d (widest first: 8/4/2 bytes):
          replace with a kernel return token | a prior-round value | a type boundary
          {0, 1, 2^31−1, 2^31, 2^32−1, 2^63−1, 2^63, 2^64−1, 0x1000, …}
  (raw tier) + hot offsets / values from the arbiter's fb.bin (magic 0xF00DDA7A)
  return hits ? d : havoc

v2 hybrid grains call it only at the stuck point (64 inputs without a new path). ret_hits stays structurally close to 0 on ksmbd: functions return NTSTATUS codes or pointers, both of which are filtered, while FIDs and resume keys travel in output buffers. cmp_hits is the reliable signal that i2s is active.

The round — crash-resilient control flow

for rnd in 1..R:
  try:
    P1  generate_grains + generate_all_grains + generate_v2_grains     # lib + raw + v2 hybrid; compile cache
    P2  run_grains(...)      per-grain libFuzzer, -procs-way, ALIGNED + PRODUCTIVE tags

        CONTRACT oracle      run_dataflow_director(): cross-user, lease, race, teardown, frag
    P3  all-pairs combine on a shared object   (final round; KSMBDZZER_P3_MAX_COMBOS budget)
  except: degrade THIS round, log it, continue
  P4  corpus_save() ALWAYS → host-durable .fuzzdb mirror

The oracle suite

OracleVerdict rule
crashKASAN / UBSAN / lockdep / BUG / refcount / GPF patterns on the serial console; panic_on_oops and hung_task_panic end the VM, and the runner resumes from .fuzzdb.
stabilityA working scenario's bare ft0 falls below half of its ratcheted baseline.
cross-user contractA root:root 0644 victim in a 0755 root directory on [privtest], with fuzz mapped to a non-root UID. OVERWRITE_IF, DELETE_ON_CLOSE and WRITE are tried through a read-only handle. The verdict comes from the effect on the backing FS (secret changed, file gone), not from NTSTATUS. A UID sanity probe runs first.
positive controlA predicate self-test (RO+OVERWRITE must flag, RW must not), plus a live RO-handle WRITE that ksmbd must reject.
lease grantThe granted state must be a subset of the requested state, and W must imply R (MS-SMB2 3.3.5.9.11).
race integrityWrite a pattern, race across pool connections, read it back; a mismatch is silent corruption.
teardown lifetimeUse a FileId after TREE_DISCONNECT or LOGOFF. STATUS_SUCCESS means a logic bug; a KASAN splat between the markers means a memory bug.
fragmented framingCREATE/WRITE/CLOSE with each PDU split across 8 TCP segments, exercising ksmbd_tcp_readv().
owner sweep (coverage only)Drives smb2_create_open_flags and i2s mapping. It never emits a finding: the 5 earlier owner-on-own-file "findings" were false positives.
