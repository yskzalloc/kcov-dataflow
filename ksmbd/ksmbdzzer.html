ksmbdzzer — a scalable SMB-procedure fuzzer for KSMBD

A high-level, SMB-procedure-level coverage-guided fuzzer for the Linux in-kernel SMB server (ksmbd), targeting write-side privilege escalation and non-crashing logic bugs. Steered by kcov-dataflow — kernel function argument/return values plus trace_cmp operand pairs, not just edges. The grain fleet covers the whole SMB1/2/3 procedure surface (99 grains), grains are combined on a shared object, and a set of engine arms lets the dataflow steering be measured head-to-head against a pc-only baseline.

Not a syzkaller. syzkaller fuzzes syscalls with edge coverage and finds crashes. ksmbdzzer fuzzes one layer up — at the SMB procedure level — with dataflow argument/return values, procedure combination, and a contract oracle for non-crashing access-control bugs. Different targets; not comparable.

Design principles

  1. SMB-procedure level, not syscall level. The atom is an SMB procedure (CREATE, WRITE, SET_INFO, IOCTL…), not a syscall.
  2. trace-args/ret is the primary signal. kcov-dataflow reports the values a kernel function saw/returned — the differentiator, and the thesis: turn a "deny"→"allow" value into a proving case. With CONFIG_KCOV_ENABLE_COMPARISONS the same buffer also carries trace_cmp operand pairs — the correct substrate for RedQueen input-to-state.
  3. KCOV path coverage for the bulk; trace-args/ret only when stuck. Cheap path coverage drives most mutation; capture the dataflow stuck point only at saturation — not every input.
  4. Grain = a working scenario. Fixed valid negotiate+auth+CREATE prefix, fuzz only the last target PDU → deep by construction, past the SMB2 parser wall.
  5. Capture normal behavior first. Seed from legitimate deep coverage; anything beyond that baseline is anomalous by construction.
  6. Four-phase round loop. P1 enumerate → P2 saturate → P3 combine → P4 save/feed-forward.
  7. Performance fuzzing in the C harness; Python only manages. The mutation/execution/feedback loop is in the LibFuzzer program; Python enumerates, launches, aggregates.
  8. LibFuzzer must see kernel coverage. Harness folds kernel KCOV into __libfuzzer_extra_counters so LibFuzzer's own engine is steered by kernel coverage.
  9. Alignment is the most important step. A grain is only as good as its prefix — keep ALIGNED (ft ≥ 100, the ALIGN_MIN_FT gate in grain/gen.py), drop misaligned. Deep-by-construction grains satisfy this by design; a grain that free-runs in-process without ever reaching ksmbd is fast-bailed instead of burning its whole budget.
  10. Anti-monkey selection. Keep/combine only mutations that beat the grain's own baseline ft0 (PRODUCTIVE); mutations adding nothing over the bare scenario are dropped.
  11. Oracles are checks, not phases. crash · stability (a normal grain that stops working = destabilization bug) · contract (write-side LPE that syzkaller is blind to).
  12. Scale via parallel map-reduce. -procs=all CPUs; per-grain loopback IP = own coverage buffer; idle cores run mutation replicas sharing one corpus.
  13. Feed-forward across generations. Persistent per-grain corpus + value pool replayed each round → starts deeper.
  14. Escape the legacy low-level fuzz smell. Old 12/8-phase random tactics → clean deep-by-construction grain loop.
  15. Lightweight data-flow-guided input-to-state steering. RedQueen driven by real trace_cmp operand pairs: input holds one operand → overwrite with the other → flip the branch (mutate_i2s pass 0). Because live grain inputs are often tiny (0–2 bytes), operands are harvested into a persistent ring and injected into a grown input window, so the splice fires fleet-wide (not just when df_buf happens to hold a cmp record). Eclipser/GREYONE boundary steering + arg/ret single-value substitution as fallbacks. No SMT, no symbolic, no byte-taint (infeasible in-kernel). cmp operands feed the mutator only — excluded from the coverage map (would explode it).
  16. Comparable, not just assertible. pc-only engine arms (edge coverage + i2s-or-havoc) run the same grains so the dataflow steering is measured, not claimed: dataflow-vec vs pc-i2s = value-coverage payoff; pc-i2s vs pc-havoc = i2s payoff. Same instrumentation, controlled ablation.

The hybrid mutator (principle 3 & 8, entirely in the C harness)

LLVMFuzzerTestOneInput(data):
    run the target PDU                       # deep by construction (grain prefix valid)
    fold kernel coverage -> ctr[]             # KCOV path + arg/ret VALUES; cmp = PC-only
    harvest trace_cmp operands -> persistent ring
    if new path:  g_stuck = 0   else:  g_stuck++

LLVMFuzzerCustomMutator(data):
    # pass 0 (RedQueen / trace_cmp): for each cmp operand pair (a1,a2),
    #   in-place replace a1<->a2 if present; else INJECT ring operands into a
    #   grown input window so the magic value reaches the branch next iteration
    then cheap KCOV-bulk havoc; at SATURATION drive an observed arg value to a boundary.

KSMBDZZER_ENGINE selects coverage+mutator so one harness runs as any of the five arms below for the engine comparison.

The grain (deep by construction)

Each grain runs negotiate → authenticate → tree-connect → CREATE as a fixed valid prefix (never fuzzed), then hands LibFuzzer the raw target PDU. Every input reaches deep ksmbd code on the first try. 99 grains cover the whole upstream SMB surface: all 19 SMB2 commands, every FSCTL and SET_INFO/QUERY_INFO class, all CREATE contexts, SMB3 features (encryption/compression/multichannel/lease-v2/ durable-v2/RDMA), SMB1 legacy opcodes (version-conflict surface), and the ksmbd blind spots (IPC netlink, signing crypto, deep DACL, RPC opnums). Canonical map: GRAIN.md. P3 combines grains pairwise on a shared handle/path — sequential, interleaved, or forked-concurrent (pfz_grain_combo2) — so interaction bugs (B abusing a lock/lease/handle A left) can surface. P3 needs -procs ≥ 2.

Scalability engineering

MechanismWhy
Per-grain loopback IP 127.0.0.<slot>ksmbd derives the kcov handle from the dest IP → unique IP = own coverage buffer, no collision. Basis for parallel map-reduce.
Map-reduce replicasWhen grains < cores, idle cores run extra mutation instances of the same grain sharing one corpus.
Compile cache (source-hash + dep-mtime)Unchanged harness ⇒ no clang. Multi-round runs compile once; later rounds go straight to fuzzing. Value pool rides the .dict, not the C source.
Fast-bail misaligned free-runnersA grain whose session never established free-runs in-process at a non-networked rate — killed as soon as the rate proves it isn't reaching ksmbd (was the dominant wasted wall-clock).
Session-drain between wavesA wave with many 0-exec grains means ksmbd hit its connection ceiling — settle proportionally before the next spawn so the auth pile-up doesn't spiral.
Lightened ksmbd restartReset only before the first wave or after a wave with a 0-exec (session-setup death) grain — not per wave. Removes restart latency and stops re-triggering the SMBDirect cleanup path each wave.

Engine comparison (measured, not claimed)

The same grains on the same kernel run under five arms (KSMBDZZER_ENGINE — a controlled ablation, identical instrumentation); engine_compare_campagin.sh prints a diff table.

ArmCoverage folded from df_bufMutator
dataflowbaseline value fold (pc ^ arg0 raw) + cmpi2s (RedQueen)
dataflow-vecwhole-arg vector fold, each field value-class-normalized (canonical value arm)i2s (RedQueen)
dataflow-reldataflow-vec + within-record pairwise cmp3 (offset<len? boundary bits)i2s (RedQueen)
pc-i2spc-only (value dropped)i2s (RedQueen)
pc-havocpc-only (value dropped)pure havoc

dataflow-vec vs pc-i2s = the value-coverage payoff (the fair, same-per-exec-cost A/B); pc-i2s vs pc-havoc = the i2s payoff (readable only when cmp_hits > 0).

PRIMARY metric = kern_pcs∪: the deduplicated fleet-wide union of distinct kernel PCs (each grain dumps its PC bitmap; gen.py ORs them). This replaces the old per-grain-popcount sum, which double-counted shared PCs and let the cheapest-per-exec engine win by cycling more grains rather than reaching more code. Secondary (engine-biased): corpus, max_ft. Proof of i2s: cmp_hits (trace_cmp splices).

Findings

Kernel defects surfaced by the campaign (write-side / IPC / RDMA teardown):
  1. ksmbd ipc_validate_msg slab-OOB read — the daemon-sized IPC response is
     cast to a fixed struct and its length fields read BEFORE the buffer is floored
     against that struct.  FIXED (floor msg_sz per event type) — transport_ipc.c
     (findings/ipc_msg_send_request_soob.md)
  2. ksmbd_alloc_user hash_sz OOB read — bound to sizeof(resp->hash).  FIXED
     (findings/ksmbd_alloc_user_sob.md)
  3. __close_file_table_ids cross-session fp UAF — foreign fp closed to the
     wrong table; new fp->ft owning-table ptr.  FIXED (findings/__close_file_table_ids_uaf.md)
  4. SMBDirect ib_cq_poll_work slab-UAF — ib_alloc_cq_any() CQs freed with
     ib_destroy_cq() (skips cancel_work_sync) so a late RXE completion re-queues poll
     work on a freed CQ.  FIXED (ib_free_cq) — connection.c
     (findings/ib_cq_completion_workqueue_uaf.md)
  5. ksmbd oplock lev-II break deadlock (srv_mutex→session_lock→m_lock→srv_mutex)
     — FIXED UPSTREAM (findings/-upstream_fixed_smb_oplock_deadlock.md)

Dataflow contract-oracle (MS-SMB2 access-control): lock-without-WRITE /
DELETE_ON_CLOSE-without-DELETE / OVERWRITE_IF-without-WRITE are real missing SMB-layer
checks but Unix-gated (ksmbd authorizes at the VFS/POSIX layer). The oracle uses a
cross-user (root-owned) victim so it can only flag a genuine LPE denial.

Quick start

100% guest-internal loopback (each worker dials 127.0.0.<octet>) — no --network flag needed.

vng --user root --memory 16G --rw --cpus 8 \
  --append "nokaslr hung_task_panic=1 hung_task_timeout_secs=60" \
  --exec 'mount -t debugfs none /sys/kernel/debug; sysctl -w kernel.kptr_restrict=0;
          python3 ../ksmbd/ksmbdzzer.py init &&
          python3 ../ksmbd/ksmbdzzer.py gfuzz -r 30 --grain-max 40'

  gfuzz -r N             generations (each carries strong grains + corpus forward)
        -procs N         parallel workers (default: ALL CPUs; P3 needs ≥2)
        --grain-max S    ceiling (s) per grain if it never saturates (default 60)
        --grain-sat R    LibFuzzer saturation ratio per grain (default 0.02)
        -t GRAIN...      restrict to a subset of grains (default: whole fleet)

  runner:  engine_compare_campagin.sh [ROUNDS] [GRAIN_MAX] [TIMEOUT_MIN_PER_ARM] [TRIALS]
           (env: PROCS P3_MAX_COMBOS REDO ARMS_OVERRIDE INSTRUMENT_ALL KSMBDZZER_ALIGNED)

The old ksmbdzzer.py fuzz (8-phase random-tactic worker + differential failslab) is legacy — retained for the failslab error-path campaign, superseded by gfuzz for the procedure-fuzzing architecture.
