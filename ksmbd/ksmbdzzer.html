ksmbdzzer — a scalable SMB-procedure fuzzer for KSMBD

A high-level, SMB-procedure-level coverage-guided fuzzer for the Linux in-kernel SMB server (ksmbd), targeting write-side privilege escalation and non-crashing logic bugs. Steered by kcov-dataflow — kernel function argument/return values plus trace_cmp operand pairs, not just edges. The grain fleet now covers the whole SMB1/2/3 procedure surface (95 grains), grains are combined on a shared object, and a second pc-only engine lets the dataflow steering be measured head-to-head.

Not a syzkaller. syzkaller fuzzes syscalls with edge coverage and finds crashes. ksmbdzzer fuzzes one layer up — at the SMB procedure level — with dataflow argument/return values, procedure combination, and a contract oracle for non-crashing access-control bugs. Different targets; not comparable.

Design principles

  1. SMB-procedure level, not syscall level. The atom is an SMB procedure (CREATE, WRITE, SET_INFO, IOCTL…), not a syscall.
  2. trace-args/ret is the primary signal. kcov-dataflow reports the values a kernel function saw/returned — the differentiator, and the thesis: turn a "deny"→"allow" value into a proving case. With CONFIG_KCOV_ENABLE_COMPARISONS the same buffer also carries trace_cmp operand pairs — the correct substrate for RedQueen input-to-state.
  3. KCOV path coverage for the bulk; trace-args/ret only when stuck. Cheap path coverage drives most mutation; capture the dataflow stuck point only at saturation — not every input.
  4. Grain = a working scenario. Fixed valid negotiate+auth+CREATE prefix, fuzz only the last target PDU → deep by construction, past the SMB2 parser wall.
  5. Capture normal behavior first. Seed from legitimate deep coverage; anything beyond that baseline is anomalous by construction.
  6. Four-phase round loop. P1 enumerate → P2 saturate → P3 combine → P4 save/feed-forward.
  7. Performance fuzzing in the C harness; Python only manages. The mutation/execution/feedback loop is in the LibFuzzer program; Python enumerates, launches, aggregates.
  8. LibFuzzer must see kernel coverage. Harness folds kernel KCOV into __libfuzzer_extra_counters so LibFuzzer's own engine is steered by kernel coverage.
  9. Alignment is the most important step. An element is only as good as its prefix — keep ALIGNED (ft≥100), drop misaligned. Grains satisfy this by design.
  10. Anti-monkey selection. Keep/combine only mutations that beat the grain's own baseline ft0 (PRODUCTIVE); mutations adding nothing over the bare scenario are dropped.
  11. Oracles are checks, not phases. crash · stability (a normal grain that stops working = destabilization bug) · contract (write-side LPE that syzkaller is blind to).
  12. Scale via parallel map-reduce. -procs=all CPUs; per-grain loopback IP = own coverage buffer; idle cores run mutation replicas sharing one corpus.
  13. Feed-forward across generations. Persistent per-grain corpus + value pool replayed each round → starts deeper.
  14. Escape the legacy low-level fuzz smell. Old 12/8-phase random tactics → clean deep-by-construction grain loop.
  15. Lightweight data-flow-guided input-to-state steering. RedQueen driven by real trace_cmp operand pairs: input holds one operand → overwrite with the other → flip the branch (mutate_i2s pass 0). Eclipser/GREYONE boundary steering + arg/ret single-value substitution as fallbacks. No SMT, no symbolic, no byte-taint (infeasible in-kernel). cmp operands feed the mutator only — excluded from the coverage map (would explode it).
  16. Comparable, not just assertible. A second pc-only engine (edge coverage + i2s-or-havoc) runs the same grains so the dataflow steering is measured, not claimed: dataflow vs pc-i2s = value-coverage payoff; pc-i2s vs pc-havoc = i2s payoff.

KSMBDZZER_ENGINE selects coverage+mutator so one harness runs as dataflow (value coverage + i2s) / pc-i2s (pc-only + i2s) / pc-havoc (pc-only + havoc) for the engine comparison.

The grain (deep by construction)

Each grain runs negotiate → authenticate → tree-connect → CREATE as a fixed valid prefix (never fuzzed), then hands LibFuzzer the raw target PDU. Every input reaches deep ksmbd code on the first try. 95 grains cover the whole upstream SMB surface: all 19 SMB2 commands, every FSCTL and SET_INFO/QUERY_INFO class, all CREATE contexts, SMB3 features (encryption/compression/multichannel/lease-v2/ durable-v2/RDMA), SMB1 legacy opcodes (version-conflict surface), and the ksmbd blind spots (IPC netlink, signing crypto, deep DACL, RPC opnums). Canonical map: GRAIN.md. P3 combines grains pairwise on a shared handle/path — sequential, interleaved, or forked-concurrent (pfz_grain_combo2) — so interaction bugs (B abusing a lock/lease/handle A left) can surface.

Scalability engineering

MechanismWhy
Per-element loopback IP 127.0.0.<slot>ksmbd derives the kcov handle from the dest IP → unique IP = own coverage buffer, no collision. Basis for parallel map-reduce.
Map-reduce replicasWhen grains < cores, idle cores run extra mutation instances of the same grain sharing one corpus.
Compile cache (source-hash + dep-mtime)Unchanged harness ⇒ no clang. Multi-round runs compile once; later rounds go straight to fuzzing. Value pool rides the .dict, not the C source.
Lightened ksmbd restartReset only before the first wave or after a wave with a 0-exec (session-setup death) element — not per wave. Removes restart latency and stops re-triggering the SMBDirect cleanup path each wave.

Findings

Kernel defects surfaced by the campaign (write-side / RDMA teardown):
  1. ksmbd oplock lev-II break deadlock — break sent under m_lock, inverting
     srv_mutex→session_lock→m_lock→srv_mutex.  FIXED (collect-under-lock) — oplock.c
  2. SMBDirect smbdirect_socket_destroy_sync recursive handler_mutex —
     listener held its cm_id handler lock while releasing children (which recurse into
     the child's handler lock) → lockdep deadlock; the 3h round-6 hang.  FIXED
     (defer child release past the handler unlock) — socket.c
  3. SMBDirect recv_io / mem-pool teardown null-deref (BUG 1)     FIXED — accept.c
  4. SMBDirect recursive &sc->listen.lock on listener teardown   FIXED (splice-then-unlock)
  5. SMBDirect cm_id UAF in _cma_cancel_listens (BUG 2)      OPEN — rare, hard RDMA-CM fix

Dataflow contract-oracle (MS-SMB2 access-control): lock-without-WRITE /
DELETE_ON_CLOSE-without-DELETE / OVERWRITE_IF-without-WRITE are real missing SMB-layer
checks but Unix-gated (ksmbd authorizes at the VFS/POSIX layer). The oracle now
uses a cross-user (root-owned) victim so it can only flag a genuine LPE denial.

Quick start

100% guest-internal loopback (each worker dials 127.0.0.<octet>) — no --network flag needed.

vng --user root --memory 16G --rw --cpus 8 \
  --append "nokaslr hung_task_panic=1 hung_task_timeout_secs=60" \
  --exec 'mount -t debugfs none /sys/kernel/debug; sysctl -w kernel.kptr_restrict=0;
          python3 ../ksmbd/ksmbdzzer.py init &&
          python3 ../ksmbd/ksmbdzzer.py gfuzz -r 30 --element-max 32'

  gfuzz -r N             generations (each carries strong grains + corpus forward)
        -procs N         parallel workers (default: ALL CPUs)
        --element-max S  ceiling (s) per grain element if it never saturates
        --element-sat R  LibFuzzer saturation ratio per element (default 0.02)

  runners:  ~/run_campaign.sh [ROUNDS] [ELEMENT_MAX]        full hunting campaign
            ~/engine_compare_campagin.sh [ROUNDS] [ELEMENT_MAX]  2-engine comparison

The old ksmbdzzer.py fuzz (8-phase random-tactic worker + differential failslab) is legacy — retained for the failslab error-path campaign, superseded by gfuzz for the procedure-fuzzing architecture.
