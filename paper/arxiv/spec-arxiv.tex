% Write a 250-word abstract for a systems security paper. The paper presents
% \toolname{}, an LLVM-based instrumentation framework that extends Linux KCOV
% with data-flow tracing of function arguments and return values.
%
% Key points to cover:
% - Problem: Edge coverage (trace-pc) is context-blind; it cannot distinguish
%   execution paths that differ only in argument values (e.g., different ioctl
%   commands reaching the same switch dispatch). This limits fuzzer exploration
%   of deep kernel state spaces.
% - Solution: A compiler pass (-fsanitize-coverage=trace-args,trace-ret)
%   that emits callbacks capturing [PC, arg_index, arg_size, pointer, struct
%   field offsets] at function entry and [PC, ret_size, pointer, field offsets]
%   at return. A separate /sys/kernel/debug/kcov_dataflow device provides
%   lock-free per-task ring buffers.
% - Dual benefit: (1) Fuzzers gain state-aware feedback for mutation guidance.
%   (2) Security analysts get deterministic argument traces for root-cause
%   analysis without printf/kprobe overhead.
% - Results: Captures all arguments including struct field expansion via DWARF
%   DICompositeType. Verified on C and Rust kernel modules. Zero interference
%   with existing KCOV/syzkaller. Overhead: <3% on lmbench micro-benchmarks
%   for instrumented modules.
% - Rust: Post-compilation pipeline (rustc→opt→llc) enables instrumentation
%   without modifying rustc, making this the only method to capture Rust kernel
%   function arguments at runtime (drgn/vmcore fails due to -O2 DWARF elision).
%
% Style: Objective, precise. No marketing language. State contributions clearly.

%% SECTION 4: SYSTEM DESIGN & ARCHITECTURE
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
%
% PROMPT:
% Write Section 4 (3 pages). This is the core technical contribution.
%
% 4.1 Overview
% - Architecture diagram description: Compiler → Kernel Transport → User-space
%   Consumer (fuzzer or analyst tool).
% - Data-flow tuple: \dftuple{PC}{arg\_idx \times arg\_size}{ptr}{offsets[]}
%
% 4.2 LLVM IR Boundary Instrumentation
% - Pass location: llvm/lib/Transforms/Instrumentation/SanitizerCoverage.cpp
% - Trigger: -fsanitize-coverage=trace-args,trace-ret
% - For each Function F with DISubprogram metadata:
%   * Extract parameter types from debug info
%   * For struct/composite types: walk DICompositeType to get field offsets
%   * Compute FNV-1a hash of type name → stored at offsets[-1] for dedup
%   * Insert call to __sanitizer_cov_trace_args(pc, arg_idx, arg_size, ptr,
%     offsets_ptr, num_fields) at function entry
%   * Insert call to __sanitizer_cov_trace_ret(pc, ret_size, ptr, offsets_ptr,
%     num_fields) before each ReturnInst
% - Handling edge cases: varargs (skip), naked functions (skip), functions
%   without debug info (skip gracefully), ERR_PTR values (detected via
%   IS_ERR_VALUE range check in kernel callback)
%
% 4.3 Lock-Free Per-Task Ring Buffer
% - Design: task_struct gains kcov_df_area (u64*), kcov_df_size, kcov_df_seq
% - Reservation: atomic_add returns slot; if slot >= size, event dropped (no
%   blocking, no allocation)
% - Record format: [seq | flags | pc | arg_idx | arg_size | num_fields |
%   field_values...]
% - Safety: notrace, __no_sanitize_coverage, noinline. All pointer reads via
%   copy_from_kernel_nofault(). No printk in data path.
% - Contexts: Safe in process, softirq, hardirq. NOT safe in NMI (disabled
%   via in_nmi() check).
%
% 4.4 Separate Device Interface
% - /sys/kernel/debug/kcov_dataflow — completely independent from /sys/kernel/debug/kcov
% - Ioctl namespace 'd': KCOV_DF_INIT_TRACE (0x80086401), KCOV_DF_ENABLE
%   (0x6464), KCOV_DF_DISABLE (0x6465)
% - mmap: user-space maps the ring buffer directly (zero-copy read)
% - No interference with syzkaller's existing KCOV usage
%
% 4.5 Rust Module Support
% - Challenge: rustc bundles its own LLVM; cannot pass custom -fsanitize flags
% - Solution: Post-compilation pipeline
%   1. rustc --emit=llvm-ir (generates .ll with DWARF debug info)
%   2. opt -passes=sancov-module -sanitizer-coverage-trace-args/ret
%   3. llc -filetype=obj → instrumented .o
%   4. Normal module linking
% - Why it works: LLVM IR is language-agnostic; our pass operates identically
%   on Rust-generated IR as on C-generated IR
% - Verified: struct field expansion works on Rust #[repr(C)] types
