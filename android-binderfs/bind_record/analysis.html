Method: Per-task function boundary extraction with CONFIG_KCOV_DATAFLOW_INSTRUMENT_ALL=y

Attack Surface

On Android, any app can open /dev/binderfs/binder and issue ioctls. kcov-dataflow captures the exact argument values flowing through the kernel during each ioctl, revealing missing validation that a user process can exploit.

Vulnerability 1: BINDER_SET_MAX_THREADS — No Upper Bound

Severity: High — Denial of Service

A user process passes max_threads=0xdeadbeef via BINDER_SET_MAX_THREADS ioctl. The kernel stores it directly into proc->max_threads without validation.

What kcov-dataflow shows:

[ENTRY] binder_ioctl(cmd=0x40046205, arg=0x7ffc...)  ← BINDER_SET_MAX_THREADS
  → copy_from_user(&max_threads, ubuf, 4)
    max_threads = 0xdeadbeef                         ← user-controlled, no check!
  → proc->max_threads = 0xdeadbeef                   ← stored directly
[RET] binder_ioctl() = 0                             ← success (should be EINVAL)

Impact: Setting max_threads=0xffffffff allows the binder thread pool to grow without limit. Each BR_SPAWN_LOOPER response creates a new kernel thread. On Android, where every app has binder access, this is a local denial-of-service (OOM kill).

Fix: if (max_threads > 256) return -EINVAL;

Vulnerability 2: BC_ENTER_LOOPER — Duplicate Accepted

Severity: Medium — State Corruption

A user process sends BC_ENTER_LOOPER twice. The kernel sets the BINDER_LOOPER_STATE_ENTERED flag both times without checking if it's already set.

What kcov-dataflow shows:

[ENTRY] binder_thread_write(cmd=BC_ENTER_LOOPER)
  → thread->looper |= BINDER_LOOPER_STATE_ENTERED   ← first time: OK
[RET] = 0

[ENTRY] binder_thread_write(cmd=BC_ENTER_LOOPER)
  → thread->looper |= BINDER_LOOPER_STATE_ENTERED   ← second time: no error!
[RET] = 0                                           ← should reject

Impact: The thread pool accounting becomes inconsistent. A thread marked as "entered" twice may not be properly tracked for requested_threads_started, leading to phantom threads that the pool manager believes are available but aren't.

Fix: Check if (thread->looper & BINDER_LOOPER_STATE_ENTERED) break;
